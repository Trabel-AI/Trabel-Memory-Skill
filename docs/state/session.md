# פתיחת שיחה

## פתוח ושבור

אין פריטים פתוחים.

## מה התחום עושה

בכל פתיחת שיחה בפרויקט עם זיכרון, הוק של התוסף מוודא שהשער פועל, ובודק אם נשארה עבודה שלא נשמרה. מה שהוא מדפיס נכנס להקשר של השיחה, ו-Claude פותח בדיווח לאדם.

## מה המשתמש רואה ועושה

- שיחה חדשה שמוצאת עבודה שלא נשמרה פותחת בדיווח קצר, בשפת האדם:
  ```
  השיחה הקודמת נעצרה לפני שמירה. השתנו 4 קבצים בתחום העמלות.
  מה הם עושים עכשיו: הדוח החודשי מחושב בשרת ונשמר בטבלה חדשה.
  לפי התור היינו בשלב 3 מתוך 5: "עמוד ההדפסה של הדוח". התיעוד עוד לא עודכן.
  ```
  אחרי הדיווח ממשיכים או שומרים, לפי מה שהאדם מחליט.
- כשהשער אינו פועל (כלי אחר שמנהל את ההוקים ולא אושר, הוק קיים שאין איפה לשמור אותו, או תיקיית נתונים שלא נמצאה), Claude אומר זאת במשפט או שניים ומציע תיקון.
- שיחה חדשה שנפתחת בבקשה להמשיך לפי התוכנית או לפי התור ("המשך על פי תוכנית", "continue from the plan") מפעילה את הסקיל `continue`. "המשך" או "continue" לבדם אינם מפעילים אותו ([plan.md](plan.md)).
- פעם אחת בכל מחשב, בשיחה החדשה הראשונה אחרי ההתקנה ובכל תיקייה, התוסף מדליק בעצמו עדכון אוטומטי לקטלוג שלו בקובץ ההגדרות של Claude Code, ו-Claude אומר זאת במשפט או שניים: שהעדכון דלוק, שגרסה חדשה נטענת בשיחה שאחרי זו שבה Claude Code מצא אותה, ואיך מכבים ([distribution.md](distribution.md)). כשההוק אינו יכול לכתוב בקובץ ההגדרות, Claude אומר במקום זה שהתוסף אינו מתעדכן לבד, ונותן את שתי הדרכים: עדכון ביד בשתי פקודות, והדלקת עדכון אוטומטי ביד. מי שכבר הדליק עדכון אוטומטי אינו מקבל שום הודעה.
- חוץ מההודעה הזאת, בפרויקט בלי זיכרון או מחוץ למאגר גיט ההוק שותק.

## נתונים והרשאות

- ההוק כותב רק את המקשר ואת עותק ההוק בתיקיית הנתונים, ואת ההוק של הגיט בפרויקט, ורק כשהתוכן שלהם השתנה; ובתיקיית הנתונים גם את הקובץ `auto-update-set`, שזוכר שההוק כבר בדק את העדכון האוטומטי במחשב הזה (הדליק, מצא דלוק, או אמר איך מדליקים ביד), ואת `settings.json.before-auto-update`, עותק של קובץ ההגדרות כפי שהיה לפני ההדלקה (ריק כשלא היה קובץ). הוא אינו משנה שום קובץ במאגר.
- בשביל העדכון האוטומטי ההוק קורא שלושה קבצים של Claude Code בתיקיית ההגדרות של המשתמש (`CLAUDE_CONFIG_DIR`, או `~/.claude`): `plugins/installed_plugins.json`, `settings.json` ו-`plugins/known_marketplaces.json`, וכותב באחד מהם, `settings.json`: הקובץ היחיד מחוץ לתיקיית הנתונים ולמאגר שהתוסף משנה. המבנה של הראשון ושל השלישי אינו מתועד רשמית, והוא נראה ב-Claude Code 2.1.278. המפתח `autoUpdate` תחת `extraKnownMarketplaces` ב-`settings.json` מתועד רשמית.
- הקלט מ-Claude Code: אובייקט JSON עם התיקייה (`cwd`) ועם `source`, שאומר איך השיחה נפתחה: `startup`, `resume`, `clear`, `compact` או `fork` (אומת מול התיעוד הרשמי).

## איך זה בנוי

`scripts/session-start.js --data <תיקיית הנתונים>`, מופעל מ-`hooks/hooks.json` ([architecture.md](architecture.md)).

1. שורש המאגר מתוך `cwd`. בלי גיט, או בלי `docs/state/settings.json`: שלבים 2 עד 5 אינם רצים.
2. **בכל פתיחה, גם ב-`compact`:** מריץ את המתקין של השער (`install` מ-`scripts/lib/hook.js`) עם הנתיב הנוכחי של התוסף. זה כותב מחדש את המקשר, כך שכל פתיחה בפרויקט כלשהו עם זיכרון מתקנת את המקשר גם בשביל פרויקט שלא נפתח זמן רב ([gate.md](gate.md)). כשהשער אינו פועל, נכתבת הערה בהקשר עם הוראה ל-Claude לספר לאדם ולהציע תיקון.
3. **בכל פתיחה חוץ מ-`compact`** (שבה זו אותה שיחה): `git status` כולל קבצים חדשים. אם יש שינויים, ההוק מזריק את רשימת הקבצים (עד 50), לכל קובץ את סוג השינוי ולכל קובץ קוד את קובץ המצב שאחראי עליו (או "no owner yet"), את התור (עד 100 שורות), והוראה לפתוח בדיווח. בלי תור הוא אומר שהכוונה של העבודה אינה כתובה בשום מקום.
4. **רק בשיחה חדשה (`startup`, `clear`):** שורה אחת בהקשר, שאומרת שבקשה להמשיך לפי התוכנית או לפי התור ("continue from the plan", "המשך על פי תוכנית") מפעילה את הסקיל `trabel-memory:continue`, וש-"continue" או "המשך" לבדם אינם מפעילים אותו, כי פירושם להמשיך בעבודה שנקטעה. כשהתור מצביע על תוכנית, השורה פותחת בנתיב התוכנית וב"session N of M", ואחריה נכתב אם קובץ התוכנית אינו קיים ומה הבעיות בצורת התור (רשימת סשנים שאינה N+1 עד M, סשן בלי משימות), כי הסקיל `continue` אינו מריץ סקריפטים ([plan.md](plan.md)). ב-`resume`, `fork` ו-`compact` השיחה כבר בעיצומה, ולכן השורה אינה נוספת. הסיבה לשורה: התיאור של הסקיל לבדו אינו מבטיח שהבקשה תפעיל אותו, והשורה היא גם המקום שבו הסקיל מקבל את מה שהסקריפט יודע על התור.
5. ההוראה ל-Claude בדיווח על עבודה שלא נשמרה: לקרוא את הדיף עצמו ולא רק את הרשימה, ולדווח אילו קבצים השתנו ובאיזה תחום, מה הם עושים, איפה התור אומר שהעבודה עמדה, והאם התיעוד עודכן.
6. **הדלקת העדכון האוטומטי** (הפונקציה `updateNote`), בכל תיקייה, רק בשיחה חדשה (`startup`, `clear`), ואחרי כל השאר:
   - העותק שרץ צריך להיות העותק המותקן: רשומה ב-`installed_plugins.json` שה-`installPath` שלה הוא תיקיית התוסף. המפתח של הרשומה (`trabel-memory@trabel`) נותן את שם הקטלוג. עותק שנטען ב-`--plugin-dir` אינו רשום שם, ולכן שותק.
   - העדכון האוטומטי נחשב דלוק כש-`autoUpdate` הוא `true` לקטלוג הזה באחד משני המקומות: `extraKnownMarketplaces` ב-`settings.json`, או הרישום ב-`known_marketplaces.json`. כשהוא דלוק ההוק אינו כותב בקובץ ההגדרות ואינו מדפיס דבר, אבל כותב את `auto-update-set`: ההוק פועל פעם אחת בכל מחשב, ומי שמכבה אחר כך נשאר כבוי.
   - אחרת (הפונקציה `turnAutoUpdateOn`): ההוק שומר עותק של `settings.json` בתיקיית הנתונים, כותב `"autoUpdate": true` ברשומה של הקטלוג תחת `extraKnownMarketplaces` (רשומה שאינה קיימת נבנית עם ה-`source` מהרישום ב-`known_marketplaces.json`), שומר את שאר הקובץ כפי שהוא (בהזחה של שני רווחים, כמו ש-Claude Code כותב אותו), כותב את `auto-update-set` ומדפיס הודעה: שם הקטלוג, הנתיב המלא של קובץ ההגדרות, איפה העותק, והוראה ל-Claude לומר לאדם שהעדכון דלוק ואיך מכבים. תיקיית הנתונים שורדת עדכון של התוסף, ולכן זה אינו חוזר אחרי עדכון.
   - ההוק מסרב לכתוב, ובמקום זה כותב את `auto-update-set` ומדפיס את ההודעה על עדכון ביד (שתי פקודות העדכון עם המזהה המלא של התוסף, ושתי הדרכים להדליק ביד), בשני מקרים: `settings.json` קיים ואינו JSON של אובייקט (קובץ שבור לעולם אינו נדרס), או שאין רשומה לקטלוג ואין לו `source` גם ב-`known_marketplaces.json`.
   - בלי תיקיית נתונים ההוק אינו כותב ואינו מדפיס דבר, כי אין איפה לזכור שזה נעשה. `installed_plugins.json` או `known_marketplaces.json` שאינם נקראים או אינם JSON נחשבים ריקים. כל תקלה אחרת: שתיקה.

הטקסט שההוק מדפיס באנגלית, כי הקורא הוא Claude ([conventions.md](conventions.md)).

## מלכודות

- **ההודעה על העדכון האוטומטי נרשמת כנאמרה כשההוק מדפיס אותה,** ולא כש-Claude אומר אותה לאדם. שיחה שבה Claude לא העביר אותה הלאה מפסידה אותה, וההסבר נשאר ב-README. ההדלקה עצמה אינה תלויה בזה: היא כבר כתובה בקובץ ההגדרות.
- **ההוק לעולם אינו מכשיל את השיחה.** כל שגיאה הופכת לשורה אחת בהקשר, וקוד היציאה תמיד 0. זמן מקסימלי: 30 שניות.
- **ההוק מתקין את השער בכל פתיחה.** הוק `commit-msg` שמישהו כתב ביד במקום ההוק של התוסף יישמר בשם `commit-msg.trabel-saved` בפתיחה הבאה.
