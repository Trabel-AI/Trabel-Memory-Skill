# הפצה

## פתוח ושבור

### לא אומת שהשורה בקובץ ההגדרות לבדה מדליקה עדכון אוטומטי
נפתח: 2026-10-01
הסיכון: התוסף כותב `"autoUpdate": true` רק ב-`settings.json`. העדכון האוטומטי עובד במחשב שבו השורה כתובה גם ב-`settings.json` וגם ברישום הפנימי של Claude Code, `known_marketplaces.json`, ולא ידוע איזה מהשניים מדליק. אם רק הרישום הפנימי קובע, משתמש חדש שומע שהעדכון דלוק, ונשאר על גרסה ישנה בלי לדעת. לפי התיעוד הרשמי השורה ב-`settings.json` מספיקה.
איך סוגרים: במחשב שבו `autoUpdate` כתוב רק ב-`settings.json`, קומיט חדש בגיטהאב מותקן לבד אחרי שיחה חדשה. אם לא, ההוק כותב את השורה גם ברישום הפנימי.
איפה בקוד: scripts/session-start.js, הפונקציה turnAutoUpdateOn

### למאגר אין רישיון
נפתח: 2026-09-30
הסיכון: המאגר ציבורי ואין בו קובץ רישיון. בלי רישיון כל הזכויות שמורות: מי שמוצא את התוסף רשאי לקרוא אותו, ואינו רשאי לפי החוק להעתיק אותו, לשנות אותו או להפיץ אותו, ואינו יודע מה מותר לו.
איך סוגרים: בעל החברה בוחר רישיון (קוד פתוח, או תנאי שימוש של החברה), והוא נכתב בקובץ `LICENSE` בשורש המאגר ומוזכר בשני ה-README.
איפה בקוד: שורש המאגר, README.md ו-README.he.md

## מה התחום עושה

המאגר נמצא בגיטהאב כ-`Trabel-AI/Trabel-Memory-Skill`, ציבורי, והוא גם התוסף וגם הקטלוג שממנו מתקינים אותו. כל קומיט שעולה לענף הראשי בגיטהאב הוא גרסה. היא מגיעה למי שמעדכן ביד, ולבד רק למי שהדליק עדכון אוטומטי לקטלוג.

## מה המשתמש רואה ועושה

- התקנה בשני צעדים, הוספת הקטלוג והתקנת התוסף. ב-Claude Code בטרמינל:
  ```
  /plugin marketplace add Trabel-AI/Trabel-Memory-Skill
  /plugin install trabel-memory@trabel
  ```
  בתוסף של VS Code הפקודה `/plugin` אינה קיימת, ואותם שני צעדים רצים מהטרמינל:
  ```
  claude plugin marketplace add Trabel-AI/Trabel-Memory-Skill
  claude plugin install trabel-memory@trabel --scope user
  ```
  בשתי הדרכים התוסף נטען בשיחה הבאה. המסלול מהטרמינל נבדק ב-Windows: הקטלוג נוסף, התוסף הותקן בהיקף user, הגרסה שהותקנה היא מזהה הקומיט, וקבצי הסקילים יצאו עם סוף שורה LF.
- אין מספר גרסה ואין שלב שחרור. Claude Code משאיר עדכון אוטומטי כבוי בכל קטלוג שאינו של Anthropic, ולכן התוסף מדליק אותו בעצמו, פעם אחת בכל מחשב, בשיחה החדשה הראשונה אחרי ההתקנה, ואומר זאת למשתמש עם הדרך לכבות ([session.md](session.md)). מאותו רגע כל גרסה מגיעה לבד.
- עדכון ביד, מהטרמינל, בכל סביבה:
  ```
  claude plugin marketplace update trabel
  claude plugin update trabel-memory@trabel
  ```
  הגרסה החדשה נטענת בשיחה הבאה, או אחרי `/reload-plugins` בשיחה פתוחה.
- המתג של העדכון האוטומטי, למי שרוצה לכבות או להדליק ביד, באחת משתי דרכים. ב-Claude Code בטרמינל: `/plugin`, Marketplaces, בחירת `trabel`, ואז Enable או Disable auto-update. בכל סביבה, כולל התוסף של VS Code שאין בו מתג כזה: השורה `"autoUpdate": true` ברשומה `trabel` שתחת `extraKnownMarketplaces` ב-`~/.claude/settings.json`. את הרשומה עצמה כותבת ההתקנה, ואת השורה כותב התוסף. התוסף מדליק פעם אחת בכל מחשב, ומי שמכבה אחר כך נשאר כבוי.
- כשהעדכון דלוק, Claude Code בודק אם יש גרסה חדשה עד עשר דקות אחרי פתיחת שיחה, והגרסה החדשה נטענת בשיחה הבאה. זה עובד בפועל מול המאגר הציבורי (Claude Code 2.1.283, Windows): במחשב עם עדכון דלוק, קומיט חדש בגיטהאב מותקן לבד אחרי שיחה חדשה, בלי שום פעולה ביד, ו-`installed_plugins.json` מראה את מזהה הקומיט החדש.
- כשהתוסף אינו יכול לכתוב בקובץ ההגדרות (הקובץ שבור, או שהקטלוג אינו רשום), הוא אומר למשתמש פעם אחת שהעדכון האוטומטי כבוי, עם שתי הדרכים: עדכון ביד והדלקה ביד ([session.md](session.md)).
- דרישות: גיט, ו-Node.js 18 ומעלה. ההתקנה אינה דורשת חשבון גיטהאב.
- שם התוסף, שהוא גם הקידומת של הפקודות, הוא `trabel-memory`. הפקודות: `setup`, `save`, `start-from-plan`, `continue`, `open`, `guide`. גם בקשה במילים מפעילה אותן. `/memory` לבדה היא פקודה מובנית של Claude Code ואינה פנויה.
- ה-README מציג בראשו את הלוגו, ומסביר את הבעיה, מה התוסף מוסיף לפרויקט, העבודה היומיומית (כולל המשך לפי התוכנית בביטוי קצר אחד, וש"המשך" לבדו פירושו להמשיך בעבודה שנקטעה), עבודה לפי תוכנית (שתי הפקודות, צורת התור, מה השער חוסם, מה נשאר שיקול דעת, ומה נכנס לתוכנית חדשה), ההתקנה, העדכונים (שהתוסף מדליק לבד, איך מכבים, ועדכון ביד), הפטורים בהודעת הקומיט, השפות, ומצב הבדיקות (נבדק ב-Windows, ההוק של הגיט לא נבדק ב-Mac וב-Linux). `README.md` באנגלית, והוא מה שגיטהאב מציג. `README.he.md` בעברית, מימין לשמאל. יש קישור מאחד לשני.

## נתונים והרשאות

- `.claude-plugin/plugin.json`: שם (`trabel-memory`), תיאור, מחבר (Trabel), קישור למאגר ולדף הבית, ומילות מפתח. בלי `version`.
- `.claude-plugin/marketplace.json`: קטלוג בשם `trabel` עם תוסף אחד, `trabel-memory`, שנמצא בשורש המאגר (`"source": "./"`). בלי `version`.
- התיאור של המאגר בגיטהאב, באנגלית: "Trabel Memory Skill. A Claude Code plugin that gives every project a memory of its current state, so each new conversation starts from it and not from zero."
- הלוגו ב-`brand/`: `Trabel-Memory-Skill-Logo-Light.png` לרקע בהיר ו-`Trabel-Memory-Skill-Logo-Dark.png` לרקע כהה. ה-README משתמש ב-`<picture>`, כך שגיטהאב מציג את הגרסה שמתאימה לרקע של הקורא. לתוסף של Claude Code אין מקום רשמי לאייקון: אין שדה כזה ב-`plugin.json` ולא ב-`marketplace.json` (אומת מול התיעוד הרשמי).
- המאגר ציבורי, ולכן כל אחד יכול להתקין ממנו כבר עכשיו, בלי אישור של החברה. החברה עצמה אינה מפרסמת את התוסף ואינה מפנה אליו אנשים מחוץ לה, עד שיהיו שבועיים-שלושה של שימוש אמיתי שמהם ידוע מה חוסם לשווא ומה חסר.

## איך זה בנוי

- **בלי `version`, בכוונה.** לפי התיעוד הרשמי, כשיש `version` משתמשים מקבלים עדכון רק כשהמספר עולה, ושיפור שעלה בלי העלאת מספר לא מגיע לאף אחד, בשקט. בלי `version` הגרסה היא מזהה הקומיט. `claude plugin validate` עוברת על המאגר וממליצה להוסיף `version`, וההמלצה נדחית. בדיקה ב-`tests/manifest.test.js` נכשלת אם `version` מופיע ב-`plugin.json` או ברשומת התוסף בקטלוג.
- **מה שעולה לענף הראשי חייב להיות בדוק**, כי אין שלב שחרור נפרד.
- **`.gitattributes`** קובע `* text=auto eol=lf` ו-`*.png binary`. ההתקנה עוברת דרך גיט אצל כל משתמש, וכך כל קובץ של התוסף יוצא עם סוף שורה LF בלי קשר להגדרות הגיט של המחשב. הסיבה: [conventions.md](conventions.md), המלכודת של CRLF.
- בהתקנה מנתיב מקומי התוסף נטען במקומו, והנתיב שלו קבוע.
- אומת מול התיעוד הרשמי (plugins, plugins-reference, plugin-marketplaces): מבנה התוסף, ההתקנה והעדכונים, השפעת `version` על עדכונים, ומבנה הקטלוג.
- **עדכון אוטומטי, מה אומת ואיפה.** בתיעוד הרשמי (discover-plugins, settings-reference, plugin-marketplaces): ברירת המחדל כבויה בקטלוג שאינו של Anthropic; המפתח `autoUpdate` ב-`extraKnownMarketplaces` תקף בכל קובץ הגדרות, גם באישי; התזמון של הבדיקה; ושבדיקת הרקע אינה משתמשת בסיסמת הגיט השמורה בחיבור HTTPS, ולכן במאגר פרטי היא עלולה להיכשל. ב-`--help` של Claude Code 2.1.278: לפקודות `claude plugin` אין דגל שמדליק עדכון אוטומטי. בקוד של אותה גרסה, ולא בתיעוד: המתג של `/plugin` שומר את הבחירה בשדה `autoUpdate` של הקטלוג ב-`~/.claude/plugins/known_marketplaces.json`, והערך מקובץ ההגדרות מועתק לשם; ובמסך `/plugins` של התוסף של VS Code יש רענון של קטלוג ואין מתג של עדכון אוטומטי.
- **בעל הקטלוג אינו יכול להדליק עדכון אוטומטי אצל מי שמתקין.** אין שדה כזה ב-`marketplace.json` וב-`plugin.json`. מדליק רק המשתמש, או מנהל ארגון בהגדרות המנוהלות. לכן התוסף אומר זאת למשתמש, וה-README מסביר איך.

## מלכודות

- **מאגר פרטי עוצר את העדכונים, גם ביד.** ב-Claude Code 2.1.283 ב-Windows, `claude plugin marketplace update` מול מאגר פרטי מנסה להוריד ב-SSH ונעצר על מפתח השרת של גיטהאב. כך גם כשגיט במחשב מחובר לחשבון עם גישה (`git ls-remote` מצליח), וגם כש-`GITHUB_TOKEN` מוגדר. באותו מחשב, מול מאגר ציבורי, אותה פקודה מצליחה. לכן המאגר ציבורי.
- **לפני שמאגר הופך לציבורי סורקים את כל ההיסטוריה שלו,** ולא רק את הקבצים הנוכחיים: סודות, נתיבים אישיים, שמות של פרויקטים פרטיים, וכתובות הדואר של כותבי הקומיטים, שנחשפות יחד עם הקומיטים.
- **קומיט שעלה לגיטהאב אינו מגיע לאף אחד בשקט,** אצל מי שלא הדליק עדכון אוטומטי ואינו מעדכן ביד. גם מחשב של מפתח התוסף הוא כזה.
- **הוספת `version` עוצרת את כל העדכונים בשקט** עד שהמספר עולה. הבדיקה ב-`tests/manifest.test.js` חוסמת את זה.
- **שני ה-README מתארים את אותו דבר.** שינוי באחד נכתב גם בשני.
