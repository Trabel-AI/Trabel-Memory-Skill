# Trabel Memory Skill

תוסף ל-Claude Code שנותן לכל פרויקט זיכרון שמתאר את הפרויקט כפי שהוא עכשיו, כך שכל שיחה חדשה מתחילה ממנו ולא מאפס.

## הבעיה

כל שיחה עם Claude Code מתחילה ריקה. התשובה המתבקשת היא תיעוד, והוא נכשל בדרך כלל באחת משתי דרכים:

- **הוא הופך ליומן.** "עודכן ב-...", "הוחלט ש...", "שינינו את X ל-Y". כדי לדעת מה נכון עכשיו, הקורא צריך לשחזר את ההיסטוריה.
- **הוא הופך לקובץ אחד גדול.** משימה אמיתית צריכה פרוסה אחת של הפרויקט: הנתונים שלה, ההרשאות שלה, המסכים שלה. כשהתיעוד מחולק לפי סוג מידע, הפרוסה הזו מפוזרת בכל מקום, ולכן כל שיחה קוראת הכל.

המבחן שמאחורי כל כלל בתוסף: האם הקורא הבא, שאינו יודע דבר, מקבל תמונת מצב, או שהוא נדרש לשחזר סיפור?

## מה הוא מוסיף לפרויקט

- **קבצי מצב**, אחד לכל תחום, ב-`docs/state/`. כל אחד מתאר את החלק שלו במוצר כפי שהוא עכשיו, בסדר קבוע: פתוח ושבור, מה התחום עושה, מה המשתמש רואה ועושה, נתונים והרשאות, איך זה בנוי, מלכודות. בראש כל קובץ כתוב על איזה קוד הוא אחראי.
- **תור**, `docs/NEXT.md`: מה עושים עכשיו. כשהוא נגמר הוא מוחלף, ולא מוארך. כשהעבודה היא לפי תוכנית בנייה, התור אומר גם באיזה סשן של התוכנית עומדים.
- **בלוק ב-`CLAUDE.md`**: כללי הכתיבה ואינדקס של קבצי המצב, כדי ש-Claude יפתח רק את הקובץ שנוגע למשימה.
- **שער בגיט**: הוק `commit-msg` שחוסם קומיט שבו הקוד השתנה וקובץ המצב שאחראי עליו לא. הוא חוסם גם סשן של תוכנית שדולג או נעלם.

ההיסטוריה נשארת במקום שלה: בגיט. הסיבה להחלטה מהותית נכתבת בהודעת הקומיט, בשורת `Decision:`.

## איך זה עובד ביום יום

1. **הקמה, פעם אחת בכל פרויקט:** `/trabel-memory:setup`. בפרויקט עם קוד, Claude מציע חלוקה לתחומים ומבקש אישור אחד, ואז כותב את קבצי המצב מתוך הקוד עצמו.
2. **עובדים כרגיל.** Claude קורא את האינדקס ופותח רק את קובץ המצב שהוא צריך.
3. **שיחה חדשה ממשיכה בביטוי קצר אחד:** "המשך על פי תוכנית", או `/trabel-memory:continue`. Claude קורא את התור, פותח רק את קבצי המצב שנוגעים למשימות, ומתחיל לעבוד. "המשך" לבדו אינו עושה זאת: זה מה שכותבים אחרי שיחה שנקטעה, ופירושו להמשיך בעבודה שנקטעה.
4. **שומרים בסוף עבודה משמעותית:** `/trabel-memory:save`, או פשוט מבקשים לשמור. Claude מעדכן את התיעוד מתוך הדיף, כותב שורות מחדש במקומן במקום להוסיף הערות מתחתן, ועושה קומיט אחד לקוד ולתיעוד.
5. **מבחן הקורא החדש.** לפני הקומיט, כל שורה שהשתנתה בתיעוד עוברת לסוכן נפרד שלא ראה את הפרויקט ולא את השיחה. שורה שמובנת רק כשינוי מגרסה קודמת, או שמספרת סיפור, נכשלת ונכתבת מחדש.
6. **שיחה שנקטעה.** שיחה חדשה שמוצאת עבודה שלא נשמרה פותחת בדיווח קצר: מה השתנה, ואיפה עומד התור.
7. **לקוד חדש יש אחראי.** קוד שאף קובץ מצב אינו אחראי עליו נתפס בשער ומקבל קובץ תחום משלו.

פקודות נוספות: `/trabel-memory:open` מציג את כל הפריטים הפתוחים בפרויקט, הישנים והמסוכנים קודם. `/trabel-memory:guide` בונה מדריך למשתמש מהסעיפים "מה המשתמש רואה ועושה".

## עבודה לפי תוכנית

בנייה גדולה נמשכת כמה שיחות. התוכנית שלה היא קובץ שכתבת, בדרך כלל במצב plan, בכל צורה ובכל אורך. התוסף רק קורא אותה: לא משתנה בה מילה בלי בקשה מפורשת שלך. איפה עומדים כתוב רק בתור.

1. **פעם אחת, בהתחלה:** `/trabel-memory:start-from-plan docs/plan.md`, או "התחל לפי התוכנית". תוכנית שכבר מחולקת לסשנים נלקחת כמו שהיא. לתוכנית שאינה מחולקת Claude מציע חלוקה, כל סשן בגודל של שיחה אחת, ומבקש אישור אחד. אם הסשן האחרון אינו שימוש במוצר מבחוץ, Claude אומר זאת ושואל אם להוסיף סשן כזה לתור. אחר כך הוא כותב את התור, עושה קומיט, ומתחיל בסשן 1.
2. **בכל שיחה חדשה:** "המשך על פי תוכנית". Claude קורא בתוכנית רק את החלק של הסשן הנוכחי, ובודק מולו את המשימות שבתור. משימה שחסרה בתור מתווספת, ואתה מקבל דיווח. זו בדיקה עצמאית, כי השיחה הזאת לא כתבה את התור.
3. **בכל שמירה:** כשכל המשימות של הסשן מסומנות, התור נכתב מחדש לסשן הבא. כשנשארו משימות, הן נשארות בראש התור ומספר הסשן אינו מתקדם. אחרי הסשן האחרון קובץ התוכנית נמחק והתוכנית יורדת מהתור, באותו קומיט. הגיט זוכר את התוכנית, ואין ארכיון.

התור כשיש תוכנית:

</div>

```
התוכנית: docs/plan.md
סשן 2 מתוך 5: מסך הלקוחות (בתוכנית: פרק 3)

- [x] טבלת הלקוחות
- [ ] טופס לקוח חדש

הסשנים הבאים:
3. הצעות מחיר (בתוכנית: פרק 4)
4. דוחות (בתוכנית: פרק 5)
5. שימוש במוצר מבחוץ, כמו משתמש חדש (בתוכנית: פרק 6)
```

<div dir="rtl">

השער חוסם תור שמצביע על תוכנית שאינה בגיט, ומספר סשן שקפץ או ירד. בלי שורת `Decision:` בקומיט הוא חוסם גם רשימת סשנים שהשתנתה בדרך אחרת מירידה של השורה העליונה שלה, קובץ תוכנית שהשתנה, ותוכנית שנמחקה או ירדה מהתור לפני שהסשן האחרון הסתיים. תור בלי הפניה לתוכנית הוא תור רגיל, והכל עובד כמו בלי תוכנית.

מה נשאר שיקול דעת, ומדווח בלי להיאכף: החלוקה לסשנים כש-Claude מציע אותה, האם נשמטה משימה בתוך סשן ("המשך על פי תוכנית" של השיחה הבאה בודק), האם משימה שסומנה בוצעה טוב (השמירה מדווחת איך נבדק, והסשן האחרון בודק מבחוץ), והאם המילים "המשך על פי תוכנית" מפעילות את פקודת ההמשך.

כשכותבים תוכנית חדשה: הסשן האחרון בתוכנית משתמש במוצר מבחוץ - כמו משתמש חדש, מאפס, על נתונים זמניים, ומנקה אחריו. הוא לא בדיקה פנימית של הקוד. מומלץ גם לכתוב את התוכנית מחולקת לסשנים, ולכתוב לכל סשן איך יודעים שהצליח.

## התקנה

המאגר הוא גם התוסף וגם הקטלוג שלו. ב-Claude Code בטרמינל:

</div>

```
/plugin marketplace add Trabel-AI/Trabel-Memory-Skill
/plugin install trabel-memory@trabel
```

<div dir="rtl">

בתוסף של VS Code הפקודה `/plugin` אינה קיימת. אותם שני צעדים, מהטרמינל:

</div>

```
claude plugin marketplace add Trabel-AI/Trabel-Memory-Skill
claude plugin install trabel-memory@trabel --scope user
```

<div dir="rtl">

בשתי הדרכים פותחים אחר כך שיחה חדשה, כדי שהתוסף ייטען. כש-`claude` אינו ב-PATH, קובץ ההרצה נמצא בתוסף של VS Code, ב-`~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/`.

דרישות: גיט, ו-Node.js בגרסה 18 ומעלה (השער והסקריפטים רצים עליו, בלי חבילות חיצוניות). ההתקנה אינה דורשת חשבון גיטהאב.

## עדכונים

כל קומיט בענף הראשי הוא גרסה, ואין מספרי גרסה. בקטלוג שאינו של Anthropic, Claude Code משאיר את העדכון האוטומטי כבוי, ולכן התוסף מדליק אותו בעצמו לקטלוג שלו, פעם אחת בכל מחשב, בשיחה החדשה הראשונה אחרי ההתקנה, ואומר לך. מאותו רגע Claude Code בודק אם יש גרסה חדשה עד עשר דקות אחרי פתיחת שיחה, והגרסה החדשה נטענת בשיחה הבאה.

**כיבוי העדכון האוטומטי**, אם רוצים: ב-Claude Code בטרמינל, `/plugin`, אחר כך **Marketplaces**, בוחרים את `trabel`, ואז **Disable auto-update**. בכל סביבה אחרת, כולל התוסף של VS Code: פותחים את `~/.claude/settings.json`, מוצאים תחת `extraKnownMarketplaces` את הרשומה `trabel`, ומוחקים ממנה את השורה `"autoUpdate": true`. התוסף מדליק פעם אחת בכל מחשב, אז זה יישאר כבוי.

**עדכון ביד**, מהטרמינל, אם גרסה חדשה אינה מגיעה:

</div>

```
claude plugin marketplace update trabel
claude plugin update trabel-memory@trabel
```

<div dir="rtl">

הגרסה החדשה נטענת בשיחה הבאה, או אחרי `/reload-plugins` בשיחה פתוחה.

## פטורים

שלוש שורות בהודעת הקומיט, תמיד באנגלית, כדי שהשער יזהה אותן בכל פרויקט:

| שורה | מתי נכתבת | מה היא עושה |
|---|---|---|
| `Docs-Unchanged: <סיבה>` | הקוד השתנה אבל ההתנהגות לא (סידור קוד, תיקון פנימי) | השער לא דורש שינוי בתיעוד |
| `Memory-Skip: <סיבה>` | רק כשהאדם ביקש במפורש לשמור בלי בדיקה | השער מדלג על הקומיט הזה |
| `Decision: <מה, מה נשקל, למה>` | התקבלה החלטה מהותית | כך מוצאים החלטות אחר כך. בשער היא רק מתירה שינוי מכוון בתוכנית או ברשימת הסשנים שלה |

לפרויקט שלם, `docs/state/settings.json` קובע את מצב השער: `block` (ברירת המחדל), `warn` או `off`. אדם יכול תמיד לעקוף את השער עם `git commit --no-verify`. השמירה הבאה משלימה את התיעוד שדולג.

## שפות

ההוראות של התוסף עצמו באנגלית. התיעוד שהוא כותב בפרויקט, והודעות השער, בשפת הפרויקט: עברית ואנגלית נתמכות, וכל שפה אחרת מקבלת הודעות באנגלית.

## מצב

נבנה ונבדק ב-Windows. ההוק של הגיט עוד לא נבדק ב-Mac וב-Linux.
